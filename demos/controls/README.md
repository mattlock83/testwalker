# Controls lab

A local, self-contained regression target for the web adapter. The plain HTML
site covers native and ARIA checkboxes/switches, radio buttons, single/multiple
selects, native dates, a custom calendar, uploads, native and ARIA sliders,
colours, HTML drag-and-drop, a custom dropdown and registration validation.

The selector-free [model](model.json) has 34 states and 85 journeys. GraphWalker
chooses the route; Jev identifies observed controls and checks results. Named
fixed examples supply dates, slider levels and colour values. The registration
data set supplies independent rules for focused Hegel tests. No runtime hook or
custom test driver is required.

## Run

From the repository root, after building Node and Rust:

```bash
cp demos/controls/run.json.example demos/controls/run.local.json
# Set decision.api_key in run.local.json to your Jev key.
npx --no-install testwalker-web demo --directory demos/controls --port 4187 --headed
```

Supply `--framework "$PWD/core/target/debug/testwalker"` if the Rust executable
isn't on PATH. The default covers the whole graph and selects six focused Hegel
attempts at confidence 0.80. Use `--input-mode none` for graph actions only, or
`--max-input-attempts 100` to select all focused partitions. Reports, screenshots,
JUnit and replay recipes are generated by Rust in `demos/artifacts/controls/`.
The owned browser and temporary website close when the run ends.

The verified live run passed all **85 edges, 34 states and six selected Hegel
attempts**, with 144 passing reported tests, 144 screenshots and no skipped or
inconclusive tests. It used 336 Jev calls at confidence 0.80. See
[the verification record](verification.json) and
[the local report](../artifacts/controls/2026-10-12T22-59-14.983Z-56579-0/report.html).
The six selected property attempts cover Name validation; all 21 focused
partitions require the larger input allowance described above.

Preview without Jev:

```bash
npx --no-install testwalker-web serve --directory demos/controls/site --port 4187
```

## What the examples demonstrate

- Checkbox/radio/switch journeys express the desired checked state. Radios are
  cleared by choosing a sibling.
- Native selects use business intent and enabled observed options. Multiple
  selects support selecting a set and clearing it.
- Native dates use literal `YYYY-MM-DD` values. The model tests a valid June
  date, an out-of-range July date and clearing. Native browser/OS popup UI is not
  needed to set the value.
- The custom calendar models opening, changing month, selecting a labelled day
  and cancelling. The custom dropdown similarly models opening and choosing an
  accessible option. These are normal observed button actions, without hooks.
- Uploads use the `travel note` and `travel documents` aliases in
  [browser.json](browser.json). Only those configured synthetic files can be
  uploaded. Paths resolve beside the browser configuration; model intents
  contain fixture names, not filesystem paths. Replacing and clearing are covered.
- Stepped sliders use keyboard operations with exact-value verification. Continuous
  native ranges use a native value setter with input/change events. The native
  range covers minimum, maximum and an interior value. The ARIA slider supplies
  a different keyboard step. Unreachable or off-step values are inconclusive.
- Native colour values use `#RRGGBB`. Trusted adapter code sets the native value
  and dispatches input/change events; the OS colour popup is not automated.
- Drag/drop uses real mouse interaction between an observed draggable item and
  a labelled list. Destination state and membership are checked independently.
- The registration form includes a multiline Notes text area as well as Name
  and Email, with independent length/format rules.
- Editing inputs and submitting forms are separate operations. All supplied
  literal inputs are validated before entry; the adapter never repairs them.

The event history records actual browser events separately from the current
scenario result. Disabled and read-only variants demonstrate unavailable
controls. Opaque widgets without usable labels, roles or exposed drag targets
still require application hooks.

## Regression tests

Tests live alongside this demo and consume the public `@testwalker/web` package:

```bash
TESTWALKER_CORE_BIN="$PWD/core/target/debug/testwalker-core" \
  npm test --workspace @testwalker/demo-controls
TESTWALKER_BROWSER_TESTS=1 \
  TESTWALKER_CORE_BIN="$PWD/core/target/debug/testwalker-core" \
  npm test --workspace @testwalker/demo-controls
```

Browser checks exercise the real controls through the adapter with deterministic
decision responses, then independently compare registration validation with
Hegel samples. The live CLI run additionally checks the Jev provider end to end.
